## 简介

Telebot 是一款用 Unity 制作的横版 2D 解谜平台游戏。核心机制是**传送弹**：射出后沿直线飞行，命中物体时玩家与它交换位置。游戏中的所有谜题，都建立在这颗子弹与被命中物体之间的交互上。

当前版本是线性的房间序列，流程约 20 分钟。底层系统是按银河恶魔城结构设计的，这也是后续的方向。

## 设计原则

游戏**没有任何文字教程**，所有机制只能通过关卡结构本身来教。三条原则支撑这一点：

### 一、一次只暴露一个身份

新组件出现时，关卡只演示它**最显性的行为**，不展示其他任何东西。

钥匙墙是一堵能被钥匙打开的实心墙。跳跃开关是一块玩家每次跳跃就切换开关的实心块。玩家一开始学到的就只有这些。

组件之间的交互、以及每个物体更微妙的性质，都被刻意保留不讲。这样玩家能建立一个干净、可靠的心智模型，同时为之后扩展这个模型留出空间。

### 二、以"不可能的局面"驱动学习

1. 玩家按照最直觉的方式尝试通过房间。
2. 尝试失败——房间看起来是无解的。
3. 要继续推进，玩家必须重新审视自己早已熟悉的组件，找到一个此前未曾考虑的性质。

失败本身就是教学时刻。游戏不会告诉玩家某个机制还有隐藏深度，而是把他放进一个"发现它是唯一出路"的局面里。

### 三、以意外驱动学习

1. 玩家正常游玩，并没有在寻找什么。
2. 某件意料之外的事情发生了。
3. 这份意外本身就传递了新信息。

这条用来处理那些"如果做成谜题反而会显得莫名其妙"的机制。与其强制玩家去发现，不如把关卡布置成让它大概率自己发生。

## 架构

在 Unity Tilemap 之上叠加一层混合网格系统，由静态事件系统驱动，玩法对象通过接口扩展。

### 网格系统

Unity 的 Tilemap 处理静态关卡几何很高效，但无法表达需要独立状态与复杂交互的对象；而如果改用纯网格实现，又要放弃 Tilemap 的编辑工具和物理集成。

Telebot 同时使用两者。**`GridManager`** 是一个单例，维护关卡的统一视图：既包含来自 Tilemap 的静态图块，也包含所有需要复杂行为的 **`GridObject`** 实例注册表。调用方可以查询任意网格坐标上有什么，而不必关心它属于哪套系统。这样玩家移动可以保持基于物理的连续运动，而谜题逻辑在离散网格坐标上求解。

关卡被划分为若干 **`Zone`**，每个 Zone 各自持有障碍 Tilemap、伤害 Tilemap、区域遮罩 Tilemap，以及自己的网格对象列表。

### 事件系统

**`GameEvent`** 是一个静态类，集中存放全局事件（C# `event`）。只涉及单个子系统的事件则保持在该子系统内部私有。这让跨系统通信是显式的，也避免模块之间互相持有直接引用。

### 扩展接口

新增玩法对象通过实现接口完成，不需要改动核心系统：

| 接口 | 作用 |
|---|---|
| `IInteract` | 对象可响应玩家的交互键 |
| `IBulletInteract` | 对象自行定义被传送弹命中时的行为 |
| `ICanDrag` | 对象可在当前房间内被玩家拖拽 |

新机制只要实现对应接口，就会被交互、传送、拖拽三大系统识别，核心逻辑零改动。目前已实现 6 类可交互组件。

### 核心系统

| 系统 | 职责 |
|---|---|
| `GridManager` | Tilemap / GridObject 混合网格，Zone 与对象注册表 |
| `GameEvent` | 全局事件广播 |
| `RoomManager` | 相机控制、房间切换、房间边界相关工具（房间尺寸固定） |
| `InputController` | 玩家状态、各状态下的合法输入、状态迁移（4 状态） |
| `TeleportBulletSystem` | 瞄准模式进出、子弹发射；`OnHitInfo` 向监听者传递命中信息 |
| `DragSystem` | `ICanDrag` 对象的拖拽模式进出 |
| `PlayerGridObj` | 玩家的网格表示，以及玩家脚下的地面对象列表 |
| `PlayerRespawnController` | 死亡与重生，回到最后记录的旗帜位置 |
| `InventorySystem` | 存放子弹修饰器 |
| `ThemeManager` / `ThemeController` | 通过 `ThemeData` ScriptableObject 切换 Global Volume 与调色板材质 |

## 着色器

**调色板替换着色器（Shader Graph）。** 精灵图以四级灰度绘制，着色器按亮度分离像素，将每个色阶重映射到任意颜色，因此运行时可以整套换色而不需要为每套配色再画一份精灵图。配合 `ThemeData` ScriptableObject，一次调用即可切换整个区域的配色——精灵、UI、Tilemap 一并生效。

## 后续计划

- **音效。** 目前完全缺失，有几个机制很需要听觉提示。
- **银河恶魔城结构。** 设计在别处学到新东西之前无法通过的房间、回溯路线，以及通过环境线索发现的隐藏房间。
- **真正的关卡。** 现有房间大多在教学，系统能承载的复杂度远超关卡目前的要求。
- **区域 2–4。** 已实现但尚未使用的机制还有不少，框架本身是为扩展设计的。
- **叙事。** 加入分镜过场来交代背景。

## 已知问题

当前构建所用的 Unity 版本存在一个上游 bug：粒子系统启用时可能抛出 Job System 错误，导致长时间游玩偶发崩溃。目前的规避方式是不使用粒子系统，后续计划升级引擎版本。
